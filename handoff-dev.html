Para el desarrollador: Este documento cubre todo lo que necesitas para tomar el mantenimiento y la evolución de gabriellattanzi.com. Es un sitio Next.js conectado a Sanity CMS y desplegado en Vercel. No se requieren conocimientos especiales fuera del stack estándar de React/Next.js.

03

Correr el proyecto en local

1

Clonar el repositorio

git clone https://github.com/mcarolarac-byte/sitiowebgabriellattanzi.git
cd sitiowebgabriellattanzi
2

Instalar dependencias (requiere Node.js 18+ y npm)

npm install
3

Crear el archivo de variables de entorno — copiar las variables que te pase el cliente y pegarlas en un archivo nuevo llamado .env.local en la raíz del proyecto. Ver sección 06 para el detalle de cada variable.

4

Iniciar el servidor de desarrollo

npm run dev

El sitio estará disponible en http://localhost:3000
El Sanity Studio estará en http://localhost:3000/studio

04

Deploy a producción

El deploy es completamente automático. Cada vez que se hace un git push a la rama master, Vercel detecta el cambio, compila el proyecto y lo publica en gabriellattanzi.com en aproximadamente 1–2 minutos.

Para publicar un cambio:

1
git add .
git commit -m "descripción del cambio"
git push
2

Vercel notifica por email cuando el deploy termina. También puedes verlo en tiempo real en vercel.com → el proyecto → pestaña Deployments.

Para agregar nuevas variables de entorno a producción: ve a Vercel → proyecto → Settings → Environment Variables. Los cambios en variables de entorno requieren un redeploy manual (botón Redeploy en el último deployment).
05

Gestión del blog (Sanity Studio)

El blog usa Sanity CMS. El cliente (Gabriel) puede crear, editar y publicar artículos directamente desde el panel de administración, sin tocar código.

Para acceder al panel de administración:

  • Ir a gabriellattanzi.com/studio
  • Iniciar sesión con la cuenta de Sanity del cliente
  • Crear un nuevo documento de tipo Post, llenar título, contenido, imagen y publicarlo
  • El artículo aparece automáticamente en gabriellattanzi.com/blog

Los leads del formulario de contacto también llegan a Sanity, en un tipo de documento llamado Lead o similar. Se pueden ver desde el mismo Studio.

Como desarrollador, el schema de Sanity está en la carpeta sanity/ del repositorio. Ahí puedes agregar nuevos tipos de contenido o campos según necesite el cliente.

06

Variables de entorno

Estas variables deben estar en el archivo .env.local para correr en local, y configuradas en Vercel para producción. El cliente debe proporcionarlas.

NEXT_PUBLIC_SANITY_PROJECT_ID
ID del proyecto en Sanity (visible en sanity.io/manage)
NEXT_PUBLIC_SANITY_DATASET
Generalmente production
SANITY_API_TOKEN
Token con permisos de escritura para guardar los leads del formulario. Generarlo en Manage → API → Tokens
NEXT_PUBLIC_TURNSTILE_SITE_KEY
Clave pública de Cloudflare Turnstile (anti-bot). Obligatoria en producción — si falta esta clave o TURNSTILE_SECRET_KEY, el formulario rechazará todos los envíos en producción
TURNSTILE_SECRET_KEY
Clave secreta de Cloudflare Turnstile. Solo en servidor, nunca expuesta al cliente

Estructura del código

src/
├── app/
│   ├── (site)/           ← Todas las páginas públicas del sitio
│   │   ├── page.tsx      ← Página de inicio (portada + hero)
│   │   ├── contacto/     ← Formulario de contacto + Calendly
│   │   ├── que-hago/     ← Servicios
│   │   ├── quien-soy/    ← Trayectoria de Gabriel
│   │   ├── blog/         ← Listado e individual de posts
│   │   └── privacidad/   ← Política de privacidad (GDPR)
│   └── studio/           ← Sanity Studio (panel de administración)
│
├── components/
│   ├── Header.tsx        ← Navegación + logo + selector de idioma
│   ├── Footer.tsx        ← Pie de página + disclaimers + LinkedIn
│   ├── LanguageSwitcher.tsx ← Botón ES/EN con banderas SVG
│   ├── Container.tsx     ← Wrapper de ancho máximo
│   └── Horizon.tsx       ← Elemento decorativo SVG
│
├── contexts/
│   └── LanguageContext.tsx ← Contexto React para ES/EN (localStorage)
│
├── lib/
│   ├── content.ts        ← Textos y datos en español (idioma base)
│   ├── content.en.ts     ← Traducción completa al inglés
│   └── i18n.ts           ← Hook useContent() — devuelve ES o EN según idioma
│
public/
├── flags/
│   ├── es.svg            ← Bandera España
│   └── gb.svg            ← Bandera Reino Unido
└── logo-gl.png           ← Logo del cliente (monograma GL)

sanity/
└── schemas/              ← Schemas del CMS (tipos de contenido)
Textos en español: editar src/lib/content.ts. Textos en inglés: editar src/lib/content.en.ts. El hook useContent() en i18n.ts devuelve automáticamente el objeto correcto según el idioma activo. La preferencia del usuario se guarda en localStorage con la clave gl-lang.
